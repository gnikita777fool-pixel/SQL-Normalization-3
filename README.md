Вот подробная пошаговая инструкция, как выполнить эту лабораторную работу в соответствии со всеми требованиями (VS Code, Git-Bash, Docker CLI, нормализация до 3НФ, логирование и оформление).

---

### **Шаг 1: Теоретическая часть (Нормализация до 3НФ)**
Эту часть нужно будет включить в ваш `README.md`. 

**Исходная таблица (1НФ):**  
`Сотрудники_Продажи (Код_сотрудника, Имя_сотрудника, Месяц, Продажи, Код_отдела, Название_отдела)`  
*Первичный ключ (ПК):* `(Код_сотрудника, Месяц)`

**Приведение ко 2НФ:**  
Во 2НФ все неключевые атрибуты должны полностью зависеть от всего первичного ключа. Устраним частичную зависимость: `Имя_сотрудника` и `Код_отдела` зависят только от `Код_сотрудника`, а не от `Месяца`.  
Разбиваем на две таблицы:
1. `Сотрудники (Код_сотрудника, Имя_сотрудника, Код_отдела, Название_отдела)`  
   *ПК:* `Код_сотрудника`
2. `Продажи (Код_сотрудника, Месяц, Продажи)`  
   *ПК:* `(Код_сотрудника, Месяц)`

**Приведение к 3НФ:**  
В 3НФ не должно быть транзитивных зависимостей (неключевые атрибуты не должны зависеть друг от друга). В таблице `Сотрудники` атрибут `Название_отдела` зависит от `Код_отдела`, который не является первичным ключом.  
Разбиваем таблицу `Сотрудники` еще на две:
1. `Отделы (Код_отдела, Название_отдела)`  
   *ПК:* `Код_отдела`
2. `Сотрудники (Код_сотрудника, Имя_сотрудника, Код_отдела)`  
   *ПК:* `Код_сотрудника`, *Внешний ключ (ВК):* `Код_отдела`

**Итоговая схема в 3НФ:**
- **Departments** (`dept_id` PK, `dept_name`)
- **Employees** (`emp_id` PK, `emp_name`, `dept_id` FK)
- **Sales** (`emp_id` PK/FK, `month` PK, `sales_amount`)

### **Шаг 2: Подготовка окружения**
1. Откройте **VS Code**.
2. Откройте терминал **Git-Bash** (в VS Code: `Terminal` -> `New Terminal` -> выберите `Git Bash` из выпадающего списка).
3. Убедитесь, что Docker запущен:
   ```bash
   docker --version
   docker ps
   ```

---

### **Шаг 3: Логирование действий**
По заданию, лог-файл должен содержать **только ваши действия** (введенные команды), без системного вывода.  
Самый надежный способ: создайте файл `actions.log` в VS Code и копируйте в него каждую команду, которую вы вводите в терминал, **перед** ее выполнением.  
Или начните новую сессию Git-Bash, выполните только команды для лабы, а затем сохраните историю:
```bash
history > actions.log
```
*(Затем откройте `actions.log` и удалите системные команды вроде `cd`, `ls`, `history`, оставив только SQL и Docker команды).*

### **Шаг 4: Практическая реализация в Docker CLI**
Выполняйте эти команды в Git-Bash (и не забывайте фиксировать их в `actions.log`):

1. **Запустите контейнер с PostgreSQL:**
   ```bash
   docker run --name postgres-lab3 -e POSTGRES_PASSWORD=mysecretpassword -d -p 5432:5432 postgres
   ```

2. **Подключитесь к интерактивной консоли БД:**
   ```bash
   docker exec -it postgres-lab3 psql -U postgres
   ```

3. **Создайте базу данных и таблицы (внутри psql):**
   ```sql
   CREATE DATABASE lab3;
   \c lab3

   CREATE TABLE Departments (
       dept_id SERIAL PRIMARY KEY,
       dept_name VARCHAR(100) NOT NULL
   );

   CREATE TABLE Employees (
       emp_id SERIAL PRIMARY KEY,
       emp_name VARCHAR(100) NOT NULL,
       dept_id INT REFERENCES Departments(dept_id)
   );

   CREATE TABLE Sales (
       emp_id INT REFERENCES Employees(emp_id),
       month VARCHAR(20) NOT NULL,
       sales_amount DECIMAL(10, 2),
       PRIMARY KEY (emp_id, month)
   );
   ```


### **Шаг 5: Создание дампа базы данных**
В терминале Git-Bash выполните команду для экспорта структуры и данных в файл:
```bash
docker exec -t postgres-lab3 pg_dump -U postgres lab3 > lab3_dump.sql
```
Убедитесь, что файл `lab3_dump.sql` появился в вашей папке (можно проверить через `ls` или в проводнике VS Code).
